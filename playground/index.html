Look inside
      

        
One tick reads the old positions and energy, computes alignment and all three rates, then returns new bounded values and positions. Rendering, clocks, and input recording live outside this function.

          
q = overlap(fish, tackle window) / fish height
F = strength × E × behavior
ΔP = (reelRate × q − escapeRate × (0.4 + F) × (1 − q)) × dt
T_target = baseTension × q + F × (0.3 + 1.1 × (1 − q))
ΔT = (T_target − T) / response × dt
ΔE = (recovery × (1 − q) × (1 − E) − fatigue × q × T × E) × dt

Tackle acceleration = (2 × lift − 1) × 3.2 − 3.8 × velocity
Fish vigor = 0.35 + 0.65 × E

          
Alignment q is derived from geometry. Hold = lift 1, release = lift 0. dt = 1/60 second. Positions, P, T, E and q stay in [0,1]; both velocities are bounded.

        

        
One shared lifecycle
Ready → waiting → bite → optional struggle → caught or escaped. A fresh press hooks the bite. Terminal states absorb input. Optional nibbles return to waiting before the real bite; hooking a nibble loses the fish.
Line break → escape → catch → timeout is the terminal precedence. A 60-second limit bounds each run and recording. Waiting at “Ready” consumes no ticks.
The Rust core runs here through WebAssembly. The native Rust build and an independent Python port are checked against shared fixtures. Fish can follow custom segment sequences, and optional nibbles add false bites before hooking. Integer state and events must match exactly; numerical checkpoints use a 1e−12 absolute tolerance. This is bounded simulation, not exhaustive model checking.
